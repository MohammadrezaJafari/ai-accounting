# AI Accounting — gateway و حسابداری توکن

یک پلتفرم شبیه GapGPT / OpenRouter برای اپ‌هایی که از هوش مصنوعی استفاده می‌کنند:

- هر مشتری یک **سازمان** است (شرکت یا شخص) با چند **عضو** و نقش. هر سازمان چند **اپ** دارد و هر اپ **کیف پول (موجودی دلاری) جدا** دارد.
- هر اپ چند **کلید API** دارد. هر کلید را می‌شود به ارائه‌دهنده‌ها یا مدل‌های خاصی محدود کرد (مثلاً فقط Claude) و برایش سقف هزینه و تاریخ انقضا گذاشت.
- برای اپ‌ها و کلیدها می‌شود **سقف هزینهٔ روزانه یا ماهانه** گذاشت. در ۸۰٪ و ۱۰۰٪ سقف به اعضای مرتبط هشدار داده می‌شود.
- اپ‌ها به‌جای OpenAI / Anthropic / Gemini، این سرویس را صدا می‌زنند (`/v1`). درخواست با **کلید واقعی ما** به ارائه‌دهنده می‌رود. توکن‌های مصرفی خوانده می‌شوند و از موجودی اپ کسر می‌شوند.
- **سود = قیمت فروش − قیمت خرید.** هر درخواست با هزینهٔ واقعی (`cost`) و مبلغ دریافتی (`charge`) در `usage_logs` ثبت می‌شود.
- شارژ موجودی با **بسته‌ها** (مثلاً ۲۰ یا ۱۰۰ دلاری، با امکان اعتبار هدیه) یا با **مبلغ دلخواه** (با حداقل و حداکثر قابل تنظیم) انجام می‌شود.

این مخزن همان الگوی پروژهٔ بیمه را دنبال می‌کند:

| بخش | فناوری | مسیر |
|---|---|---|
| پنل مدیریت | Filament 5 (فارسی، وزیرمتن، تاریخ جلالی، ساعت تهران) | `/admin` |
| API پنل مشتری | Laravel + Sanctum، مصرف‌کننده: [ai-accounting-web-app](https://github.com/MohammadrezaJafari/ai-accounting-web-app) (Quasar) | `/api/v1` |
| Gateway مدل‌ها | سازگار با OpenAI و Anthropic | `/v1` |

## قیمت‌گذاری

قیمت‌ها **دلار به ازای هر ۱ میلیون توکن** هستند و برای چهار دسته جدا تعریف می‌شوند: ورودی، ورودی کش‌شده، نوشتن کش و خروجی.
قیمت خرید هر مدل را همان قیمت رسمی ارائه‌دهنده وارد کنید. قیمت فروش به این ترتیب تعیین می‌شود:

1. **درصد سود اختصاصی اپ** (قرارداد ویژه): قیمت خرید × (۱ + درصد اپ)
2. **قیمت فروش ثابت مدل**، اگر ادمین وارد کرده باشد
3. قیمت خرید × (۱ + درصد سود **مدل** ← **ارائه‌دهنده** ← **پیش‌فرض عمومی** در «تنظیمات مالی»)

مبالغ در دیتابیس به‌صورت عدد صحیح **nano-USD** ذخیره می‌شوند (۱ دلار = ۱۰^۹)، تا قیمت هر توکن دقیق بماند. مبلغ دریافتی رو به بالا گرد می‌شود.

> قیمت‌های `CatalogSeeder` قیمت‌های اعلام‌شده در زمان نوشتن هستند. قبل از استفادهٔ واقعی آن‌ها را در پنل بررسی کنید.

## استفاده از Gateway در اپ‌ها

```python
# OpenAI SDK — برای همهٔ مدل‌ها (GPT، Claude، Gemini، DeepSeek، Grok)
from openai import OpenAI
client = OpenAI(base_url="https://YOUR-HOST/v1", api_key="sk-aia-...")
client.chat.completions.create(model="claude-sonnet-4-5", messages=[{"role": "user", "content": "سلام"}])
```

```python
# Anthropic SDK — API اختصاصی Messages برای مدل‌های Claude
import anthropic
client = anthropic.Anthropic(base_url="https://YOUR-HOST", api_key="sk-aia-...")
client.messages.create(model="claude-sonnet-4-5", max_tokens=1024, messages=[{"role": "user", "content": "سلام"}])
```

| Endpoint | توضیح |
|---|---|
| `GET /v1/models` | مدل‌هایی که این کلید اجازهٔ استفاده از آن‌ها را دارد |
| `POST /v1/chat/completions` | قالب OpenAI، با پشتیبانی از stream. برای Anthropic و Gemini از endpoint سازگار با OpenAI خودشان استفاده می‌شود |
| `POST /v1/messages` | قالب Anthropic، با پشتیبانی از stream (فقط ارائه‌دهنده‌ای که `native_format = anthropic` دارد) |

- اگر موجودی اپ صفر یا کمتر از حداقل باشد، خطای `402` برمی‌گردد.
- در حالت stream، گزینهٔ `stream_options.include_usage` خودکار فعال می‌شود تا مصرف قابل محاسبه باشد.
- اگر ارائه‌دهنده گزارش مصرف نفرستد (مثلاً چون کلاینت وسط کار قطع شده)، مصرف تخمین زده می‌شود (حدود ۴ کاراکتر برای هر توکن) و در لاگ علامت می‌خورد.

## سازمان‌ها و نقش‌ها

هر کاربر هنگام ثبت‌نام یک سازمان می‌سازد و مالک آن می‌شود. هر کاربر می‌تواند عضو چند سازمان باشد. API پنل همیشه روی **سازمان فعلی** کاربر کار می‌کند.

| کار | مالک | توسعه‌دهنده | مالی |
|---|:-:|:-:|:-:|
| دیدن اپ‌ها، مصرف، لاگ‌ها و اعضا | ✓ | ✓ | ✓ |
| ساخت و ویرایش اپ | ✓ | ✓ | |
| کلیدهای API و سقف هزینهٔ کلیدها | ✓ | ✓ | |
| چت پنل | ✓ | ✓ | |
| کیف پول، شارژ، سفارش‌ها، تراکنش‌ها و سقف هزینهٔ اپ‌ها | ✓ | | ✓ |
| اعضا، دعوت‌ها و نام سازمان | ✓ | | |

- **دعوت:** مالک ایمیل و نقش را وارد می‌کند. لینک دعوت (`PANEL_URL/invite/{token}`) ایمیل می‌شود و در پاسخ API هم برمی‌گردد تا بشود دستی فرستاد. دعوت را فقط کاربری می‌تواند بپذیرد که با همان ایمیل وارد شده باشد. لینک ۷ روز اعتبار دارد.
- هر سازمان همیشه دست‌کم یک مالک دارد.

## سقف هزینه

- **اپ:** سقف روزانه یا ماهانه. این سقف را مالک یا نقش مالی تعیین می‌کند.
- **کلید:** سقف کل (در طول عمر کلید)، روزانه یا ماهانه. این سقف را مالک یا توسعه‌دهنده تعیین می‌کند.
- روز و ماه به وقت تهران حساب می‌شوند و **ماه، ماه شمسی است**. سقف ماهانه اول هر ماه شمسی صفر می‌شود.
- با پر شدن سقف، gateway خطای `402` برمی‌گرداند.
- وقتی سقف یا دورهٔ آن عوض شود، مصرف دورهٔ فعلی از روی لاگ‌ها دوباره حساب می‌شود.
- **هشدار:** در ۸۰٪ و ۱۰۰٪ سقف، در هر دوره یک بار، اعلان ایمیلی و درون‌پنلی فرستاده می‌شود. هشدار اپ به مالک و نقش مالی می‌رسد و هشدار کلید به توسعه‌دهنده‌ها هم.

## بازارچهٔ ایجنت‌ها (فروش بر اساس واحد)

ایجنت محصولی است که به ازای **واحد** فروخته می‌شود، نه توکن (مثلاً یک گزارش). پلتفرم نقش **درگاه** را دارد و خود ایجنت‌ها لازم نیست در این کد باشند:

- **ایجنت خارجی (HTTP):** سرویسی جدا که خودمان یا یک ناشر دیگر اجرا می‌کند. ادمین آن را در پنل (ایجنت‌ها) تعریف می‌کند: آدرس سرویس، معرفی در بازارچه، ناشر و درصد سهم او، مدل‌های مجاز، سقف هزینه، و **پارامترهایی که مشتری پر می‌کند**. ناشر می‌تواند همهٔ این‌ها را در یک فایل manifest منتشر کند تا با دکمهٔ «بارگذاری از manifest» وارد شوند.
- **ایجنت داخلی:** پیاده‌سازی داخل همین کد. فعلاً فقط «پایش خبر» (`news-monitor`) داخلی است.

کارهای پلتفرم برای همهٔ ایجنت‌ها یکسان است: فروش بسته و نگه‌داری اعتبار، فرم پارامترها و اعتبارسنجی آن، زمان‌بندی، دسترسی به مدل‌ها با قیمت واقعی، نگه‌داری حافظهٔ ایجنت بین اجراها، ارسال خروجی به تلگرام، بله، ایمیل و وب‌هوک، و اعلان‌ها.

- سازمان **بستهٔ واحد** را از کیف پول یکی از اپ‌هایش می‌خرد (مثلاً ۳۰ گزارش به ۹ دلار). هر اجرا پیش از شروع یک واحد نگه می‌دارد. اگر ایجنت چیزی تحویل ندهد یا خطا بدهد، واحد برمی‌گردد. ایجنت می‌تواند بگوید خروجی‌اش چند واحد می‌ارزد (تا سقف «حداکثر واحد در هر اجرا»).
- درخواست‌های مدلِ هر اجرا با **هزینهٔ واقعی و مبلغ دریافتی صفر** در `usage_logs` ثبت می‌شوند و به همان اجرا (`agent_run_id`) وصل‌اند. **سقف هزینهٔ هر اجرا** جلوی واحدهای زیان‌ده را می‌گیرد.
- در پنل ادمین برای هر ایجنت درآمد، هزینه، سهم ناشر، سود، میانگین هزینهٔ هر واحد و هزینه‌ای که ۹۵٪ واحدها کمتر از آن هستند نمایش داده می‌شود.

**پارامترهای ایجنت** (`config_schema`): فهرستی از فیلدها با `key`، `label`، `type`، `required`، `section`، `hint`، `placeholder`، `default` و بسته به نوع `options`، `min`/`max` یا `max_items`. نوع‌ها: `text`، `textarea`، `number`، `select`، `multiselect`، `tags`، `url`، `url_list`، `toggle` و `secret`. فرم پنل مشتری از همین تعریف ساخته می‌شود. مقدار فیلدهای `secret` (مثلاً کلید API سرویس مشتری) به ایجنت فرستاده می‌شود ولی هیچ‌وقت در API پنل برنمی‌گردد.

### پروتکل ایجنت خارجی

**۱. درخواست اجرا.** در هر اجرا پلتفرم به `endpoint_url` این درخواست را می‌فرستد:

```http
POST {endpoint_url}
X-Agent-Slug: competitor-watch
X-Agent-Timestamp: 1790000000
X-Agent-Signature: sha256=<HMAC-SHA256("{timestamp}.{body}", signing_secret)>

{
  "event": "run",
  "run": {"id": 42, "trigger": "schedule", "deadline": "2026-10-01T08:15:00+00:00"},
  "agent": {"slug": "competitor-watch", "unit_name": "گزارش", "max_units": 5},
  "instance": {"id": 7, "name": "رقبای فروشگاه"},
  "organization": {"id": 3, "name": "شرکت نمونه"},
  "config": {"domain": "https://shop.example", "competitors": ["a.example"]},
  "state": {"cursor": 12},
  "locale": "fa", "timezone": "Asia/Tehran",
  "platform": {
    "token": "agr_…",
    "result_url": "https://api.example/agent-api/runs/42/result",
    "llm_base_url": "https://api.example/agent-api/v1",
    "default_model": "gpt-4o-mini"
  }
}
```

سرویس باید امضا را بررسی کند و درخواستی را که timestamp آن بیش از چند دقیقه اختلاف دارد رد کند. کلید امضا در صفحهٔ ایجنت در پنل ادمین است. دکمهٔ «تست اتصال» درخواستی با `{"event": "ping"}` می‌فرستد و انتظار پاسخ 2xx دارد.

**۲. نتیجه.** سرویس یا در همان پاسخ (HTTP 200، تا «مهلت پاسخ مستقیم») نتیجه را برمی‌گرداند، یا با **HTTP 202** کار را می‌پذیرد و نتیجه را تا `deadline` با توکن اجرا به `result_url` می‌فرستد (`Authorization: Bearer agr_…`):

```json
{
  "status": "succeeded",
  "report": "## گزارش\n… (Markdown)",
  "units": 1,
  "items": 7,
  "notes": ["۷ صفحه بررسی شد."],
  "warnings": ["سایت b.example در دسترس نبود."],
  "state": {"cursor": 19},
  "data": {"prices": []}
}
```

- `status`: یکی از `succeeded`، `empty` (چیز تازه‌ای نبود، واحدی مصرف نمی‌شود) یا `failed` (همراه با `error`؛ واحد برمی‌گردد).
- `report` برای `succeeded` لازم است و به مقصدها فرستاده می‌شود.
- `units` تعداد واحد مصرفی است. پیش‌فرض ۱ است و از سقف ایجنت بیشتر حساب نمی‌شود.
- `state` حافظهٔ ایجنت است که در اجرای بعد برمی‌گردد. اگر نفرستید، حافظهٔ قبلی می‌ماند.
- `data` خروجی ساخت‌یافته است که در بدنهٔ وب‌هوک مقصدها هم فرستاده می‌شود.
- حجم `state` و `data` هر کدام حداکثر ۲۵۶ کیلوبایت است.

اولین نتیجه ثبت می‌شود و بعد از آن توکن از کار می‌افتد. اجرایی که تا مهلت نتیجه نفرستد ناموفق ثبت می‌شود و واحدش برمی‌گردد.

**۳. دسترسی به مدل‌ها.** ایجنت برای صدا زدن مدل‌ها کلید جدا لازم ندارد. کافی است OpenAI SDK را به `llm_base_url` وصل کند و توکن اجرا را به‌عنوان API key بدهد (`POST /agent-api/v1/chat/completions`، بدون stream). هزینه به همان اجرا نوشته می‌شود و فقط مدل‌های مجاز ایجنت در دسترس‌اند.

```python
client = OpenAI(base_url=payload["platform"]["llm_base_url"], api_key=payload["platform"]["token"])
```

آدرس‌های `result_url` و `llm_base_url` از `APP_URL` ساخته می‌شوند، پس `APP_URL` باید آدرسی باشد که سرویس ایجنت به آن دسترسی دارد.

**manifest ناشر** (اختیاری) یک فایل JSON با `name`، `tagline`، `description`، `icon`، `category`، `publisher: {name, url}`، `unit_name`، `max_units_per_run`، `endpoint_url` و `config_schema` است.

**پارامترهای پایش خبر (ایجنت داخلی):**

| پارامتر | توضیح |
|---|---|
| منابع | تا ۱۰ آدرس فید RSS/Atom یا صفحهٔ خبری. از صفحه‌های خبری تیترها (لینک‌ها) خوانده می‌شوند |
| کلیدواژه‌ها و کلیدواژه‌های حذفی | خبرهایی که یکی از کلیدواژه‌ها را دارند نگه داشته و آن‌هایی که یکی از کلیدواژه‌های حذفی را دارند کنار گذاشته می‌شوند |
| تازگی (`max_age_hours`) | خبرهای قدیمی‌تر از این تعداد ساعت نادیده گرفته می‌شوند |
| تعداد خبر، سطح جزئیات (`brief` یا `detailed`)، زبان گزارش (`fa` یا `en`)، دستورالعمل آزاد | |

**تنظیمات مشترک همهٔ ایجنت‌ها:** زمان‌بندی (ساعت‌های روز و روزهای هفته به وقت تهران، مثلاً ۸ و ۲۰ از شنبه تا چهارشنبه)، توقف و اجرای دستی، و `notify_empty` (وقتی چیز تازه‌ای نیست هم به مقصدها پیام داده شود).

**مقصدهای ارسال خروجی** (هر ایجنت می‌تواند چند مقصد داشته باشد، و برای هر مقصد دکمهٔ «ارسال آزمایشی» هست):

- **تلگرام و بله:** شناسهٔ کانال یا گروه. ربات پلتفرم (`TELEGRAM_BOT_TOKEN` و `BALE_BOT_TOKEN`) را به کانال اضافه و ادمین کنید، یا توکن ربات خودتان را وارد کنید. توکن‌ها رمزنگاری‌شده ذخیره می‌شوند و در API برگردانده نمی‌شوند.
- **ایمیل:** تا ۱۰ نشانی.
- **وب‌هوک:** یک درخواست POST با بدنهٔ JSON (`event`، `report` به Markdown و …) و امضای `X-Signature` برابر با HMAC-SHA256 بدنه با کلید مخفی همان مقصد. برای اتصال به n8n، Zapier، Slack و ابزارهای دیگر.

خطای یک مقصد اجرا را ناموفق نمی‌کند. نتیجهٔ ارسال به هر مقصد در اطلاعات همان اجرا ذخیره می‌شود.

**اجرای زمان‌بندی‌شده** به cron نیاز دارد: `* * * * * php artisan schedule:run` (دستور `agents:run-due` هر دقیقه ایجنت‌های موعدرسیده را اجرا و اجراهای از مهلت گذشته را ناموفق می‌کند). اجرای دستی از پنل، بعد از فرستادن پاسخ HTTP انجام می‌شود و به worker صف نیاز ندارد.

## پرداخت

درگاه با `BILLING_PAYMENT_GATEWAY` انتخاب می‌شود:

- `manual`: سفارش در وضعیت «در انتظار» می‌ماند تا ادمین در پنل (سفارش‌ها ← «تأیید پرداخت») تأییدش کند.
- `fake`: سفارش فوراً پرداخت‌شده ثبت می‌شود. فقط برای توسعه.

برای اضافه‌کردن درگاه واقعی (زرین‌پال، Stripe، کریپتو و …)، `App\Services\Payments\PaymentGateway` را پیاده‌سازی کنید و آن را در `PaymentManager` ثبت کنید. callback درگاه باید در نهایت `OrderService::markPaid()` را صدا بزند. این متد idempotent است.

## راه‌اندازی

```bash
composer install
cp .env.example .env && php artisan key:generate
php artisan migrate --seed        # ادمین: admin@example.com / password (ADMIN_EMAIL / ADMIN_PASSWORD)
php artisan serve
```

بعد از راه‌اندازی:

1. وارد `/admin` شوید.
2. در بخش «ارائه‌دهنده‌ها»، کلیدهای واقعی OpenAI / Anthropic / Google را اضافه کنید.
3. قیمت‌ها و درصد سود را بررسی کنید.

تست‌ها:

```bash
php artisan test
```
